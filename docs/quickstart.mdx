# Quickstart

**One binary on the host, one on the client, a directory you can `ls` over the internet — no VPN.** The same `gmountie` binary plays both roles. End-to-end is about 90 seconds.

:::note[Prerequisites]
- **Server:** Linux on amd64 or arm64.
- **Client:** Linux *or* macOS. FUSE on the client:
  - Linux: `fuse3` (`apt install fuse3` on Debian/Ubuntu).
  - macOS: [macFUSE](https://macfuse.io) *or* [FUSE-T](https://www.fuse-t.org/).
- A folder you want to share on the server, plus an empty mount point on the client.
:::

## 1 · Install

Build from source (Go 1.26+):

```bash
git clone https://github.com/gMountie/gMountie && cd gMountie
go build -o gmountie ./cmd
```

Or grab the release archive for your platform from the [releases page](https://github.com/gMountie/gMountie/releases) — `gmountie_linux_*.tar.gz` for Linux, `gmountie_darwin_*.tar.gz` for the macOS client. The binary is `gmountie` (lowercase); on Linux it's both the server and the client, and on macOS it's the client (the `serve` subcommand is Linux-only).

## 2 · Start the server

**Zero-config first run:** just run `gmountie serve` with no arguments. On first start it auto-generates `~/.config/gmountie/server.yaml`, creates a `shared` volume at `$XDG_DATA_HOME/gmountie/shared`, generates a random admin password, and prints it **once** to the console. The hash is stored in the config — you never need to write it down.

```bash
gmountie serve
# First run: generated config at ~/.config/gmountie/server.yaml
# Admin password (save this — shown once): <random>
```

Or write your own `server.yaml` from the start:

```yaml title="server.yaml"
server:
  address: 0.0.0.0
  port: 9449
auth:
  type: basic
  users:
    - username: admin
      password_hash: $argon2id$v=19$m=19456,t=2,p=1$...  # output of: gmountie genpass
volumes:
  - name: shared
    path: /srv/shared
```

Then start it:

```bash
gmountie serve -c server.yaml
```

The server listens on `:9449` and exposes `/srv/shared` as the volume `shared`. It also auto-generates a TLS cert on first run — the fingerprint is logged at startup.

:::tip[Rotating the password]
Run `gmountie genpass`, copy the printed `$argon2id$…` string, and paste it into `auth.users[0].password_hash` in your config. The server rejects any value that doesn't start with `$argon2id$` — no plaintext passwords are ever stored.
:::

## 3 · Mount the volume from a client

Use the shorthand form — the password is prompted interactively with no echo:

```bash
mkdir -p ~/mnt/shared
gmountie mount admin@your-server.example:9449/shared ~/mnt/shared
# Password: (enter the password printed on first server run)
```

`~/mnt/shared` now behaves like a local folder — every read, write, and `stat` flows to the server over a TLS-wrapped gRPC stream:

```bash
ls ~/mnt/shared          # listing comes from /srv/shared on the server
cat ~/mnt/shared/file    # bytes stream over the wire
```

To see what volumes a server exposes before mounting:

```bash
gmountie ls admin@your-server.example:9449
```

Press `Ctrl-C` in the `gmountie mount` terminal to unmount cleanly, or run `umount ~/mnt/shared` from another shell. To mount in the background, add `--daemon` — the process detaches once the mount is ready and logs go to `$XDG_STATE_HOME/gmountie/mount-daemon.log`.
