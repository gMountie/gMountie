# OSS Module-Path Rename Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the Go module path from the bare, non-resolvable `gmountie` to
the vanity import path `go.gmountie.dev/gmountie`, so the library becomes
importable by external consumers (the closed cloud repo) — with zero behavior
change and all existing tests green.

**Architecture:** A mechanical, repo-wide rename. The module line in `go.mod`
changes; every internal import (`"gmountie/..."` → `"go.gmountie.dev/gmountie/..."`)
is swept; generation configs (`.mockery.yml`) and generated artifacts (gRPC
stubs, mocks) are updated/regenerated; the build + full test suite verify no
behavioral change. A separate one-time infra step (the `<meta go-import>` vanity
redirect on the `.dev` site) is what makes external `go get` work, but is *not*
required for this repo's own build/tests.

**Tech Stack:** Go (module `gmountie` today), `go-task` (`Taskfile.yaml`),
protoc + protoc-gen-go/-go-grpc (`task gen:grpc`), mockery v3.7.0
(`task gen:mocks`), golangci-lint (`task lint`).

**Why first:** This is the single prerequisite for the cloud repo to `import`
the OSS `pkg/...` types. It unblocks every later S0 OSS feature and all of S1/S2.
Land it before anything else. See `gMountie-cloud/docs/design/oss-changes.md`.

## File Structure

This rename is best done in an isolated worktree (per repo convention:
worktree + PR per feature). Files touched:

- `go.mod` — the `module` line (the one source of the new path).
- **All `*.go` files importing the module** (183 files) — every
  `"gmountie/..."` import string rewritten to `"go.gmountie.dev/gmountie/..."`.
- `.mockery.yml` — the `dir:` `trimPrefix "gmountie/"` and every interface
  package key (`gmountie/pkg/...`).
- `internal/mocks/**` — regenerated (do **not** hand-edit; blown away by
  `task gen:mocks`).
- `pkg/proto/*.pb.go` — regenerated by `task gen:grpc` (the `.proto`
  `go_package = "pkg/proto"` is *relative* and needs no edit; regen confirms
  consistency).
- *(No source-relative string literals of the module path are expected outside
  imports; Step 3 greps to confirm.)*

**Not in this PR (separate infra task, tracked in `oss-changes.md`):** serving
the `<meta name="go-import" content="go.gmountie.dev/gmountie git https://github.com/gMountie/gMountie">`
redirect from the `.dev` site. Required before the cloud repo can `go get`, but
not for this repo's local build/tests.

### Task 1: Rename the module path

**Files:**
- Modify: `go.mod` (module line)
- Modify: all `*.go` with `"gmountie/..."` imports (183 files)
- Modify: `.mockery.yml`
- Regenerate: `pkg/proto/*.pb.go`, `internal/mocks/**`

- [ ] **Step 1: Create the worktree + branch**

Use the `superpowers:using-git-worktrees` skill (or native worktree). Branch
name: `oss-module-rename`. Work entirely inside the worktree.

- [ ] **Step 2: Capture a green baseline (so we can prove "no behavior change")**

Run (from the repo root, in an environment with `/dev/fuse` — CI runners and the
user's plain terminal have it; a sandbox/GoLand does not, per project notes):

```bash
go build ./... && go vet ./... && go test ./... 2>&1 | tail -5
```

Expected: build/vet clean, tests PASS. If any test is already red **before** the
rename, stop and report — the rename must not be blamed for pre-existing failures.
(If you lack `/dev/fuse` locally, run the non-e2e packages:
`go test $(go list ./... | grep -v '/test/e2e') 2>&1 | tail -5` and defer the
full suite to CI — noted again in Step 9.)

- [ ] **Step 3: Confirm the rename surface (imports only, no stray literals)**

```bash
grep -rl '"gmountie/' --include='*.go' . | wc -l          # expect 183
grep -rn 'gmountie/' --include='*.go' . | grep -v '"gmountie/' | grep -v _test.go | head
grep -rn '\bgmountie\b' go.mod .mockery.yml
```

Expected: 183 files with quoted imports; the second grep shows no *code*
references to the bare path outside import strings (comments/strings are fine to
leave but note any); `go.mod` line 1 is `module gmountie` and `.mockery.yml` has
the `trimPrefix "gmountie/"` + the `gmountie/pkg/...` keys.

- [ ] **Step 4: Rewrite the module line in `go.mod`**

Change the first line of `go.mod`:

```
module gmountie
```

to:

```
module go.gmountie.dev/gmountie
```

- [ ] **Step 5: Sweep every Go import**

Rewrite the quoted import prefix across all Go files (the trailing `/` ensures we
only touch import paths, never the bare word in comments):

```bash
grep -rl '"gmountie/' --include='*.go' . \
  | xargs sed -i 's#"gmountie/#"go.gmountie.dev/gmountie/#g'
```

Verify none remain and the new prefix is present:

```bash
grep -rn '"gmountie/' --include='*.go' . | head        # expect: no output
grep -rl '"go.gmountie.dev/gmountie/' --include='*.go' . | wc -l   # expect 183
```

- [ ] **Step 6: Update `.mockery.yml`**

`.mockery.yml` references the old prefix in two places: the `dir:` template
(`trimPrefix "gmountie/"`) and every interface package key. Rewrite both:

```bash
sed -i 's#trimPrefix "gmountie/"#trimPrefix "go.gmountie.dev/gmountie/"#' .mockery.yml
sed -i 's#^\(\s*\)gmountie/pkg/#\1go.gmountie.dev/gmountie/pkg/#' .mockery.yml
```

Confirm:

```bash
grep -n 'gmountie' .mockery.yml    # every line should read go.gmountie.dev/gmountie/...
```

- [ ] **Step 7: Regenerate gRPC stubs and mocks**

The `.proto` `go_package` is relative (`"pkg/proto"`) so the `.proto` files need
no edit, but regenerate to confirm the stubs are consistent under the new module;
then regenerate the mocks (which were swept by name but are authoritative only
when regenerated):

```bash
task gen:grpc
task gen:mocks
```

Expected: both complete without error. `git status` shows regenerated files under
`pkg/proto/` and `internal/mocks/` (content identical except any import lines now
carry the new path).

- [ ] **Step 8: Tidy and build**

```bash
go mod tidy
go build ./...
go vet ./...
```

Expected: `go.mod`/`go.sum` settle with the new module path; build + vet clean.
If `go build` reports an unrewritten `gmountie/...` import, fix that file (a
generated file Step 7 should have covered, or a path the sed missed) and re-run.

- [ ] **Step 9: Run the full test suite (prove no behavior change)**

```bash
go test ./... 2>&1 | tail -5
```

Expected: PASS — identical result to the Step 2 baseline. (E2E `fs` suites need
`/dev/fuse`; if running where it's unavailable, run
`go test $(go list ./... | grep -v '/test/e2e')` here and rely on CI for the
FUSE e2e suites — they exercise no module-path logic, so a green build + unit
suite is strong evidence.)

- [ ] **Step 10: Lint**

```bash
task lint
```

Expected: clean (the rename introduces no new lint issues).

- [ ] **Step 11: Commit**

```bash
git add -A
git commit -m "refactor: rename module gmountie -> go.gmountie.dev/gmountie

Make the library importable via a resolvable vanity path (a bare name is not
go-gettable). Sweep all internal imports, update .mockery.yml, regenerate gRPC
stubs and mocks. No behavior change; full test suite unchanged.

Breaking change for any external importer (none exist yet); documented in
release notes. The go.gmountie.dev <meta go-import> redirect is a separate infra
task and is required before downstream repos can go get this module."
```

- [ ] **Step 12: Open the PR**

```bash
gh pr create --fill
```

In the PR description, note: (a) this is the S0 prerequisite for gMountie-cloud
imports; (b) the **vanity redirect on `.dev` is a separate follow-up** that must
land before any external `go get`; (c) it's a no-behavior-change rename verified
by the unchanged test suite.
