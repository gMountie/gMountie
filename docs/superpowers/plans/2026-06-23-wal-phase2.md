# WAL — Write-Delegation Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the on-disk WAL that lets a delegation holder defer mutating ops and flush them in pipelined batches, collapsing the per-file `open→write→close` RTT that dominates small-file WAN workloads — on top of Phase 1's coherence layer, with no new data-loss class beyond local-FS-power-loss semantics.

**Architecture:** Client-side, a per-`(identity,volume)` WAL (durable op-log) + an in-memory `memfs`-shaped **pending overlay** serve read-your-own-writes as `base ⊕ pending`. The delegation+WAL+overlay layer moves **outer of the cache** (correct-by-construction: the overlay is consulted first, the cache below holds only base). Server-side, a client-streaming `Apply` RPC replays/flushes batched ops through a shared `applyOp`, deduped by a **durable seq-watermark** and fenced by **delegation generation**, both in a bbolt `WatermarkStore` behind a cloud-swappable option seam. `close()` defers; `fsync`/recall/size/interval flush.

**Tech Stack:** Go; gRPC (`pkg/proto`, `task gen:grpc`); bbolt (`go.etcd.io/bbolt`, already a dep via the cache persist tier); `memfs` node-tree shape for the overlay; testify suites; `pkg/utils/log` (`log.Log`, zap).

## Global Constraints

- **Builds on Phase 1** (merged): the delegation `Manager`, `Arbiter`, `RecallRegistry`, `RpcFs.Recall` bidi stream, the `posWritePath` layer, and the cache `DelegationOracle`/`InvalidateSubtree` seams all exist. Do not duplicate them.
- **No backward compatibility** — change the proto freely; clients/servers upgrade together.
- **Overlay placement = OUTER of the cache.** The delegation+WAL+overlay layer sits between `posObserver` and `posCache` (a new enum ordering in `compose.go`). The cache holds only `base`; the overlay is the single source of truth for un-flushed state. NEVER make the cache materialize pending (no write-through, no invalidation-completeness obligation).
- **WalOps are PATH-based, not fd-based** — replay needs no client→server fd remapping; the server's `Apply` handler materializes any transient fd internally per op.
- **`Apply` is client-streaming with ONE terminal `ApplyAck`** (not bidi/per-op). Persist-before-ack: the server persists the watermark to the store BEFORE returning the ack. On first apply-failure the server `SendAndClose`s early with `{committed_watermark, failed_seq, fserr}`; the client treats further `Send` errors as "stop, read the ack."
- **The seq-watermark AND the revoked-gen set live in ONE durable store** keyed by `(identity, volume)`. If they diverge, fencing breaks.
- **Loud data-loss logging (§5.1 of the spec) is mandatory and tested**: on ANY un-flushed-WAL discard, an ERROR `log.Log` enumerating the EXACT lost file paths (not a count) + cause + seq range + `(identity,volume)`, plus a `WalDataLost` metric. A count-only or path-omitting log is a test failure. (Extends the existing `Release` sticky-error loud log.)
- **`fsync` is the durability truth-point**, not plain `close()` (fsyncgate; POSIX-legal). Deferral trades close-time error fidelity for speed.
- **Logging** via `pkg/utils/log` (`log.Log`); **errors** wrapped with `github.com/pkg/errors`.
- **Tests are testify suites**; root-gated server FS tests skip when not root. Race-test concurrent code (`-race`). Never hand-edit `internal/mocks/` — regenerate via `task gen:mocks`.
- **Server durable state is single-node** (bbolt); multi-replica HA is the cloud `WatermarkStore` impl's concern via the option seam, not built here.

- [ ] **Step 1: Add the messages + RPC to `fs.proto`.**

```proto
// WalOp is one deferred mutating op replayed/flushed via Apply. PATH-BASED:
// it reuses the existing unary request messages (which carry volume + path +
// caller), so the server needs no client fd mapping. seq is the client's
// monotone per-(identity,volume) sequence; gen is the delegation generation the
// op was deferred under (fences superseded replay). request_id (already on each
// inner message) still drives idempotency.
message WalOp {
  oneof op {
    CreateRequest      create       = 1;
    WriteOp            write        = 2;   // path-based write (see below)
    MkdirRequest       mkdir        = 3;
    RmdirRequest       rmdir        = 4;
    UnlinkRequest      unlink       = 5;
    RenameRequest      rename       = 6;
    SymlinkRequest     symlink      = 7;
    SetAttrRequest     set_attr     = 8;
    SetXAttrRequest    set_xattr    = 9;
    RemoveXAttrRequest remove_xattr = 10;
    ReleaseOp          release      = 11;  // deferred close (path-based)
  }
  uint64 seq = 20;
  uint64 gen = 21;
}

// WriteOp is a path-based write (the deferred form of WriteAndFlush): no fd,
// the server opens/writes/closes internally during Apply.
message WriteOp {
  string volume     = 1;
  Caller caller     = 2;
  string path       = 3;
  int64  offset     = 4;
  bytes  data       = 5;
  string request_id = 6;
}

// ReleaseOp marks a deferred close — flushes any final state for path. Mostly a
// no-op marker today (the create/writes already carry the bytes) but reserved so
// the WAL records the full lifecycle.
message ReleaseOp {
  string volume     = 1;
  Caller caller     = 2;
  string path       = 3;
  string request_id = 4;
}

message ApplyAck {
  uint64  watermark  = 1;  // highest seq durably applied (persisted before this ack)
  uint64  failed_seq = 2;  // 0 == no failure
  FsError fserr      = 3;  // FS_OK unless an op failed (ordered halt)
}
```

Add to `service RpcFs { ... }`:
```proto
  // Apply replays/flushes a batch of deferred WAL ops. Client-streaming: the
  // client pipelines WalOps in seq order and half-closes; the server applies in
  // order (dedup ≤ watermark, fence revoked gen), persists the watermark, then
  // returns ONE ApplyAck. On first failure it SendAndCloses early.
  rpc Apply (stream WalOp) returns (ApplyAck);
```

`store.go`:
```go
// Package watermark is the server-side durable store for the WAL replay
// seq-watermark and the revoked delegation-generation set, per (identity,
// volume). The watermark dedups replayed ops (≤ watermark = no-op); the revoked
// gens fence superseded replays. They live in ONE store: if they diverge,
// fencing breaks. Default impl is embedded bbolt (OSS, self-contained); the
// cloud injects a centralized impl via the server option seam.
package watermark

type Key struct{ Identity, Volume string }

type Record struct {
	Watermark   uint64
	RevokedGens []uint64
}

type Store interface {
	Get(k Key) (Record, error)
	// Advance raises the watermark to max(current, watermark), durable (fsync)
	// before return — the persist-before-ack invariant.
	Advance(k Key, watermark uint64) error
	// RevokeGen records gen as revoked, durable (fsync) before return — the
	// persist-before-handoff invariant.
	RevokeGen(k Key, gen uint64) error
	Close() error
}
```

`bbolt.go`: open `bolt.Open(path, 0o600, &bolt.Options{Timeout: time.Second})` (NOTE: NOT NoSync — this store must fsync; rely on bolt's default sync-on-commit, and `db.Update` commits durably). Bucket `"wm"`. Key bytes = `identity + "\x00" + volume`. Encode `Record` with `encoding/json` (small, stable). `Get` via `db.View`; `Advance`/`RevokeGen` via `db.Update` (read-modify-write the record). Wrap errors with `errors.Wrap`.

```go
func OpenBBolt(path string) (Store, error) {
	db, err := bolt.Open(path, 0o600, &bolt.Options{Timeout: time.Second})
	if err != nil {
		return nil, errors.Wrap(err, "open watermark bbolt")
	}
	if err := db.Update(func(tx *bolt.Tx) error {
		_, e := tx.CreateBucketIfNotExists([]byte("wm"))
		return e
	}); err != nil {
		_ = db.Close()
		return nil, errors.Wrap(err, "create wm bucket")
	}
	return &bboltStore{db: db}, nil
}
// keyBytes, Get (View+json.Unmarshal), Advance (Update: read rec, if wm>rec.Watermark set+put),
// RevokeGen (Update: read rec, append-if-absent, put), Close. bolt's Update commits
// durably (msync+fsync) by default — satisfies persist-before-ack.
```
