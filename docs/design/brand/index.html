§ I · The Idea

A network filesystem that doesn't ask much of you.

gMountie is a small server you run beside your data, and a small client you run on your laptop. The client mounts a named volume from the server as a regular directory. Syscalls go over gRPC; bytes go back the same way. There is no setup ritual. There is no S3-compatibility layer to learn. There is no daemon you forget about and have to debug six months later.

The metaphor we keep in mind: a small, tireless courier who shuttles your files to wherever you happen to be. The courier does not ask why you are on a train in another country. It picks up the page you ask for and brings it back. Then it waits for the next one.

Today gMountie is a developer-grade tool you self-host. In time it will be a cloud service, for the days you would rather not run a server. Both will speak the same protocol.

Client mounts a volume; server serves it. That is the whole architecture.

§ III · The Ledger

What it gives you. What it doesn't.

01 A real filesystem.

Mounted as a FUSE filesystem on Linux. Open, read, write, stat, fsync — your existing tools work. No new client library to learn.

02 Honest about the wire.

gRPC with Snappy compression. Configurable auth (none, basic, mTLS). You can tcpdump a session and see what is going on.

03 Volume-scoped, multi-tenant.

Each request carries a volume name. One server, many volumes, isolated per-request — no session state to fight with.

04 macOS & Windows: not yet.

Linux is the only supported target today. macOS via macFUSE is on the roadmap. We will not ship "soon" — we will ship "now" when it works.

05 Strong consistency: not yet.

gMountie reads through a small client cache. Distributed locking and strong cross-client consistency are a phase-two concern.

06 A cloud version: in time.

Open source is the product today. A hosted offering is in design for teams who would rather not run a server. Same wire format.

§ IV · Getting started

Three commands. One filesystem.

01 / SERVER  Serve a directory

Run this beside the data you want to share.

$ go install gmountie/cmd/gmountie@latest
$ gmountie serve --volume photos=/srv/photos \
            --listen 0.0.0.0:8443 --auth basic
# serving 1 volume on :8443

02 / CLIENT  Mount it anywhere

Same binary, different verb. Mount at any local path.

$ gmountie mount photos ~/photos \
            --server fs.example.com:8443
# mounted volume 'photos' at ~/photos

$ ls ~/photos
# … your files, on your laptop.
§ V · The note

Why we built this.

From the field journal · entry 47
I keep a server at home with a few terabytes of photographs, recordings, archives — the things you accumulate when you do not throw anything away. When I am out of the house I want them the way I want my own hands: there when I reach for them. The existing options were a VPN tunnel pretending to be a LAN, or syncing a copy and then forgetting which copy was the original. Both felt wrong. So I wrote the small thing that did the small job, and gMountie is what it became.
— John, in a café in Athens, 2024
